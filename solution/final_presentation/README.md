# Final Phase — Executive Business Presentation

Translates the six-phase platform into a leadership-facing artefact: the
operational/financial problem, the end-to-end architecture, headline SQL + EDA
insights, model performance in money and risk terms, the revenue-optimisation
case, and the governance/deployment story — primarily as a single-page site,
so it stays live, linkable and always current with the repo, plus a companion
slide deck covering the same content for offline / in-meeting use.

## Deliverables

`site/` — a static, dependency-free HTML/CSS page (no build step) sourced
directly from each phase's own findings and headline numbers. Deployed to
**GitHub Pages** by [`.github/workflows/pages.yml`](../../.github/workflows/pages.yml)
on every push to `main`.

**Live site:** https://code-4-fun.github.io/capstone-healthcare-analytics/

`site/Hospital_Ops_Revenue_Risk_Platform.pptx` — a 15-slide deck (title,
agenda, business problem, architecture, one slide per phase reusing that
phase's own chart from `site/assets/charts/`, business impact, governance,
build status, close) built directly from this page's content. It lives inside
`site/` so it deploys with the page and is linked from the top nav as
**Slide Deck ⇩**, downloadable straight off the live site. Regenerate it
(`build_deck.py`, see below) after updating `site/index.html` so the two stay
in sync — it is generated, not hand-edited.

## Structure

```
site/
  index.html            the page: hero, problem, architecture diagram,
                         phase-by-phase walkthrough, business impact,
                         governance, build status
  Hospital_Ops_Revenue_Risk_Platform.pptx
                         the companion slide deck, linked from the top nav
                         (generated by ../build_deck.py — see below)
  assets/style.css       house style, reusing capstone.viz's CVD-validated
                         palette (src/capstone/viz.py) for visual continuity
                         with every phase's charts
  assets/charts/*.png    one or two representative charts per phase, copied
                         from that phase's own output/charts/ (never
                         regenerated or edited — see the source phase for the
                         full chart set and underlying CSVs)
build_deck.py            generates site/Hospital_Ops_Revenue_Risk_Platform.pptx
```

## Updating it

The page is hand-authored, not generated by a script — unlike the phase
notebooks, there is no new quantitative analysis here, only a curated summary
of numbers and charts each phase already produced and verified. When a phase's
headline numbers change (a rerun with new data, a retrained model), update the
corresponding section in `site/index.html` and re-copy the referenced chart
from that phase's `output/charts/` — the source of truth stays each phase's
own `PHASE<n>_FINDINGS.md`, never this page.

## Why a site, plus a deck

`docs/PLAN.md`'s Final Phase originally called for slides + a one-page brief +
an architecture diagram. The site is the primary, always-current deliverable —
reproducible (checked into the same repo, deployed the same way as every other
phase) and shareable as a link rather than a file, matching the platform's own
"one command reproduces everything" ethos. The `.pptx` sits alongside it for
the settings a link doesn't cover — presenting to a room, sending an
attachment — and mirrors the site's content exactly, so there is still one
source of truth to keep current.

## Regenerating the deck

The deck is built with [`python-pptx`](https://python-pptx.readthedocs.io/),
which is not a project dependency (it's a presentation-authoring tool, not
part of the analytics platform). Build it in a throwaway virtualenv:

```bash
python3 -m venv /tmp/pptxgen_venv
/tmp/pptxgen_venv/bin/pip install python-pptx
/tmp/pptxgen_venv/bin/python solution/final_presentation/build_deck.py
```
